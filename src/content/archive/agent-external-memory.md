dsh 是一个"一切皆插件"的 agent harness，我很喜欢它的极简路线。问题是上游不接受外部 PR，而我又想让它记住跨会话的东西。这篇文章复盘我的解法：dsh-memory，一个 MCP stdio 服务器，给 dsh 以及任何 MCP 宿主（Codex、ZCode）装上同一套长期记忆。

## 不碰上游，是最省力的参与方式

既然上游不收 PR，那就把记忆做成宿主无关的基础设施：模型通过 7 个 MCP 工具读写记忆，宿主只需要支持 MCP 协议。目前它已经接进三个宿主——dsh 走 cordis overlay patch，Codex 走 config.toml，ZCode 走 config.json。检索和归档全是本地确定性代码，运行成本 0 token。

## 两层记忆：数据库是真相，Markdown 是地图

SQLite 是唯一真相源；Markdown 文件（MEMORY.md 导航、PENDING.md 收件筐、journal 流水）是从数据库派生的"地图"，给人类和其他工具看的。两层一致性靠一个叫 `markdown_outbox` 的机制保证：数据库写入和"同步文件的意图"在同一个事务里提交，失败了重启后补齐。

这个设计的直觉是：**地图不是百科全书**。模型每次拿到的只是 ≤1600 字的导航块，细节靠它自己用搜索工具按 uid 溯源。

## 写入门卫：默认不信任

记忆系统最大的风险不是忘掉，而是记住错的东西还越攒越自信。门卫规则包括：11 类条目白名单；shared 域强制证据（没有原文短引的观点会被真实拒绝）；三层去重；correction 必须指向被修正的条目，且在同一事务里把旧记录转成 superseded。

一次真实验证里，模型自发调用工具记住了测试口令，但拒绝把它升级为"用户偏好"——证据等级不够。一个会拒绝的记忆系统，才值得长期使用。

## 诚实的评测，包括负结果

评测集是 16 条 golden 查询加 13 条合成核心集，语料指纹绑定防止在旧语料上复用旧标签。成绩：recall@3/5 = 1.000，MRR 从 0.927（81 条活跃快照）涨到 0.969（84 条）。

但更有价值的是负结果：

- 统一覆盖阈值 0.5 会把 hit@5 拉低到 0.800——所以**决定不启用**，决策留在文档里；
- 词面误召回是测明的能力边界："火星土壤的颜色"这种查询会只命中"颜色"两个字。

所有成绩都标注了"开发回归集，不可与 mem0/zep/locomo 等通用基准互换"。一个只在自己的小测验里拿高分的系统，诚实标注考场范围，是它能被改进的前提。

## 现状

22 次提交，156 项测试全绿，journal 从 9 月 9 日连续记到现在——系统在被真实使用。下一步最划算的不是加功能，是喂它：数据层 mindbase 还有一万多条候选知识等着批量提取入库，记忆变厚之后，才谈得上向量语义层（双路融合的接口已经预留好了）。

## 尚未解决的问题

- 使用反馈闭环已建成，但真实反馈目前是 0 条——开发回归集上的成绩和真实使用分布差多少，只有喂更多真实查询才知道。
