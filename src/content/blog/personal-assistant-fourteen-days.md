9 月 20 日第一次提交，10 月 4 日本机装着 v0.15.0 日常使用。这中间是 54 次提交和 557 个测试方法。这篇文章记一下 personal-assistant 这条线是怎么走过来的，以及几个我现在仍然认同的决定。

## 起点是两份文档，不是一行代码

7 月先有一份项目交接说明，9 月中旬又写了一份架构设计 v0.1，然后才开始写代码。验收标准也不是拍脑袋：拿 JYY GSE2026 Lab1「会成长的个人助手」的五项能力（资料索引检索、邮箱关联、事务办理、手机联动、能力组合）逐条对照过一遍。

先写文档的好处是，很多"做到一半发现不对"在动笔阶段就暴露完了。

## 刻意不搞微服务

整个后端是一个约 70 个模块的模块化单体：渠道无关的统一事件入口、SQLite 状态保存、任务状态机，往上是摄取（QQ 索引、只读 IMAP 邮件）、规划（今日计划、周概览、提醒策略）、记忆（候选→审核→事实三段式，证据逐字短引，纠错走 superseded 链）、阅读线、跨 agent 交接，入口是 FastAPI 静态工作台加 Telegram bot。

依赖只有 5 个 Python 包。单用户、本机运行的产品，微服务除了让调试变慢什么也给不了。

## 验证方式：不联网，不烧 token

557 个测试全部用假的 LLM 客户端和替身 IMAP/SMTP 跑，不联网、不花钱。另有一套个人 benchmark：用自己的真实数据测"模型 + 提示词 + 管道"的联合质量，分三层——免凭据自检、确定性检索、真实模型——二元评分，退出码非 0 可以直接接 CI。

一个体会：**测试替身的投入永远值回票价**。邮件全链路（增量收取、线程关联、模型起草、逐版人工确认、一次性凭据发送）能肆无忌惮地改，靠的就是替身。

## 桌面化是另一面墙

Web 工作台变成桌面应用，过的是工程关不是产品关：PyInstaller 把 Python 后端打成 sidecar，Tauri 2 做宿主，NSIS 出安装包；会话凭据走匿名管道，进程树用 Job Object 回收，随机端口加实例身份握手防止串台。每一项都不难，但每一项漏了都是事故。

## 还没做完的

写作本文时，工作区还有一百多处未提交改动等着整理入库，启动页三方案没拍板，更远的 roadmap 上躺着桌宠、信息雷达和向量检索。但这个项目最让我满意的部分不是功能列表，而是它从第一天起就在被真实使用——包括被我自己。

工具只有在日常里活下来的，才算真的做完了第一版。
